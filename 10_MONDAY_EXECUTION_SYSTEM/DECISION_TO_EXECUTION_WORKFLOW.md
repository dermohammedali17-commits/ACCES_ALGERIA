# DECISION TO EXECUTION WORKFLOW

> Standard process for converting strategic decisions into executable actions.

---

# 1. CORE FLOW

STRATEGIC FINDING
↓
ANALYSIS
↓
DECISION
↓
ACTION
↓
OWNER
↓
DEADLINE
↓
EXECUTION
↓
RESULT
↓
REVIEW

---

# 2. DECISION RECORD

Every important decision should identify:

- Decision
- Reason
- Evidence
- Decision Maker
- Date
- Consequence
- Next Action

---

# 3. ACTION CREATION

An approved decision should produce one or more clearly defined actions.

Each action should contain:

- Action
- Owner
- Deadline
- Expected Result
- Priority
- Related Project

---

# 4. EXECUTION

Actions are managed through Monday.

---

# 5. RESULT CAPTURE

When an action is completed:

1. Record the result.
2. Update the project.
3. Record important new knowledge.
4. Update GitHub where appropriate.

---

# 6. DECISION REVERSAL

A decision may be revisited when:

- New evidence appears
- Assumptions change
- Regulations change
- Market conditions change
- Execution becomes infeasible

---

# 7. CORE PRINCIPLE

A decision is not complete until the required action has been executed or formally cancelled.
